# System audit and hardening, 2026-10-11

Scope: build system (Maven), runtime/network topology, backend (Spring Boot 4.0.8 / Java 21), database migrations, UI,
tests and documentation. Method: full source read; compilation of all main and test code against the exact Spring
Boot 4.0.8 dependency set recovered from the original build; execution of all pure-logic unit tests; Spring's own
exception-handler resolver; a functional test of the Maven wrapper against a stand-in distribution.

## Findings and status

| # | Sev | Area | Finding | Status |
|---|---|---|---|---|
| 1 | High | Build | No Maven wrapper or root build; only worked with a matching global Maven; no enforcer/coverage | Fixed: `mvnw`, root aggregator, enforcer (Java 21+, Maven 3.9+), JaCoCo, build-info, CI workflow |
| 2 | High | Network | PostgreSQL published on host with a hard-coded password; app published on all interfaces while defaulting to unauthenticated demo | Fixed: DB has no host port; internal `data`/`edge_app` networks; proxy bound to loopback by default; secrets via `.env` |
| 3 | High | Security | Insecure default: `APP_DEMO_DATA` defaulted to `true` (unauthenticated API) | Fixed: defaults to `false`; demo is opt-in via profile/env; startup message explains how |
| 4 | High | Function | Non-demo mode could never work: nothing created the tenant or any integration account, so no inverter could be added | Fixed: idempotent `TenantBootstrap` (tenant by `TENANT_ID` + one LIVE account per brand) |
| 5 | High | Reliability | Poller held one DB transaction across every account's network calls; a DB error rolled back all accounts; vendor data length could break inserts | Fixed: snapshot -> network (no tx) -> per-account persist; truncation, null guards, per-account failure isolation |
| 6 | High | Data | Telemetry grew without bound and had no uniqueness constraint | Fixed: V7 dedupes then adds unique `(device_id, timestamp)`; nightly batched retention keeps newest per device |
| 7 | Med | Network | No outbound HTTP policy for OEM adapters (timeouts, redirects, SSRF via configurable `baseUrl`) | Fixed: `OutboundHttpClient` + `OutboundUrlValidator`, wired into the live-adapter boundary |
| 8 | Med | API | Unexpected exceptions had no handler; no correlation ids; validation errors unhelpful | Fixed: single problem+json contract, safe 500 fallback, `X-Request-Id` in headers/logs/body, field messages |
| 9 | Med | Data | Moving an inverter to another project left its purchase cost in the old project's ledger | Fixed in `syncPurchaseCost` (rejects cross-currency moves) |
| 10 | Med | Perf | Dashboard loaded entire site/project lists just to count them | Fixed: count queries |
| 11 | Med | Ops | No graceful shutdown, no readiness/liveness probes, no container healthcheck, root-writable container | Fixed: graceful shutdown, probes, healthcheck, read-only fs, dropped capabilities |
| 12 | Med | Docs | OpenAPI covered 13 of 26 operations | Fixed: regenerated from the controller |
| 13 | High | Security | `auth_config_json` can hold OEM credentials in plaintext; no secret abstraction | **Open** (nothing writes it today). Before any live adapter: store a secret reference (vault/KMS), not credentials |
| 14 | High | Security | Authentication is one shared key, no users/roles/tenant membership | **Open**. Required before customer-facing SaaS (OIDC/Keycloak) |
| 15 | High | Function | All OEM live connectors are stubs (by design: no verified credentials/APIs); ECT unverified | **Open** (needs vendor approvals) |
